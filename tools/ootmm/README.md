# Pinned entrance metadata

The exporters require a local OoTMM v32.3 checkout whose HEAD is exactly
`413573d22d1d53e8a81931a70927f625b73488b9`. They read immutable Git blobs with
`git show`, so checkout line endings and uncommitted file edits cannot alter the
source digest. Python 3 and Git are the only dependencies; there is no network or
reference-checkout mutation. Unrecognized registry syntax fails closed.

Run from this repository, substituting the path to that checkout:

```sh
python tools/ootmm/export_registry.py --reference /path/to/ootmm-stable-32.3
python tools/ootmm/export_grotto_context.py --reference /path/to/ootmm-stable-32.3
python tools/ootmm/export_registry.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_grotto_context.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_entrance_settings.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_solver_contract.py --reference /path/to/ootmm-stable-32.3
python tools/ootmm/export_solver_contract.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_oot_wallmaster_sources.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_mm_wallmaster_spawn.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_oot_bindings.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_m1_contract.py --reference /path/to/ootmm-stable-32.3 --check
```

`--output-root` defaults to this repository and can point at a scratch directory.
`--check` compares exact LF UTF-8 bytes and exits unsuccessfully on missing or stale
output without writing files. Formatting of generated tables is deterministic and
does not depend on a locally installed formatter. Narrow `.gitattributes` rules
preserve canonical LF output even in Windows checkouts using `core.autocrlf=true`.

The registry exporter writes `combo/rando/entrances/Registry.h`, its upstream
license, and `registry-source.json`. The context exporter validates the 13 generic
grotto content codes, 24 source-qualified MM exits, and mountain winter exception
against the pinned runtime before writing `GrottoMetadata.h` and its manifest.
Other native binding/arrival adapters are not outputs of these exporters.

Compared with the previous 611-row master registry, v32.3 has 608 rows. The removed
records are unused type-none `OOT_BOSS_GANONDORF`, `MM_BOSS_MAJORA`, and `MM_BOSS_IGOS`.
Seven OoT records have different area metadata. All remaining MM records retain
their semantic fields; the extracted MM grotto runtime tables are identical.

Existing MM-only saved profiles and their oracle assumptions deliberately keep
the old master commit and historical CRLF-byte hash in `LegacyEnvelope.h`. Their
writers, readers, profile names, and schema versions retain that contract. The
legacy fixture in `ComboAndroid/tests/fixtures/entrances-legacy-v1.json` was captured
before the repin and must not be regenerated by an exporter. The current registry
identity is available for a future unified format; this change does not enable
that format or any public entrance settings.

Host coverage is registered in `ComboAndroid/tests/CMakeLists.txt`: legacy profile
and route compatibility, compiled registry/context metadata, and exact-reference
export reproducibility with wrong-pin and stale-output rejection. The reference
test uses `COMBO_OOTMM_REFERENCE` or discovers `references/ootmm-stable-32.3` in an
ancestor directory. It reports an explicit skip when that optional checkout is
absent; compiled metadata and legacy-route checks still run.

The independent settings exporter reads the same pinned revision's
`packages/core/src/settings/data.ts`. It writes `OotmmSettingsData.inc` and the
`ootmm-32.3-entrance-settings.json` host fixture; omit `--check` to regenerate them.
Its optional destination flag is `--root`. The fixture retains all 44 reference
rows, while the hidden C++ catalog contains the 40 in-scope settings. Warp songs,
soaring spots and altered Lost Woods exits stay deferred. Every capability bit
is off, so the guarded reader cannot enable an unfinished pool. This model is
preparation for later menu/profile/headless integration, not a new public menu.

`entrance_hidden_settings_reference_parity` compares compiled names, descriptions,
choices and stable enum values with the fixture and evaluates 1,288 normalization
cases against the original reference conditions. It also verifies that correcting
the shared default booleans preserves the private v1 helper's existing pools.
The solver exporter records the pinned polarity sets, spawn/Wallmaster destination
type changes, retry bounds, and opposite-age Temple starting-item requirement in
`ComboAndroid/tests/fixtures/ootmm-32.3-solver-contract.json`. The executable host
fixture checks joint pool selection, the 10-backtrack/1000-attempt bounds, selected
accessibility, and MM arrival/reset behavior against that contract. The OoT Temple
case tests the required callback boundary with a small graph; a native OoT graph
adapter remains unavailable. OoT/Both shuffles with active logic therefore reject
a missing Temple callback before sampling. This foundation does not complete M0
or enable public entrance controls or a new playable entrance format.

The OoT Wallmaster exporter parses the exact runtime source-classification function
with a deliberately restricted C grammar and records it, its canonical blob hash,
six scene/room rules, and 13 registry identities in `oot-wallmaster-source.json`.
This source manifest also serves as the offline test fixture. The executable test
compares all 7 x 256 scene/actor-room combinations (six known scenes plus Unknown)
against both the parsed fixture and the compiled upstream function. Unsupported
syntax, unknown source metadata, wrong pins and stale generated bytes are rejected.

`OotWallmasterSource.h` is a private classifier only. It has no native actor hook,
layout installer, graph adapter, transition or public capability. A future caller
must pass `Actor.room`, reject the native ShadowTag enhancement, and preserve the
existing respawn unless a validated route exists. The 23 incoming OoT logic edges
(11 vanilla, 12 MQ), opposite-age Temple validation, and native destination/context
support must still be completed before enabling OoT Wallmaster shuffling. In
particular, Forest MQ hallway keys and Ganon Spirit's capture-specific conditions
cannot be inferred from similarly named native regions.

The MM Wallmaster spawn exporter preserves the pinned `mm/actors.c` clear-flag hook
and its soul-gated caller in `mm-wallmaster-spawn-source.json`. The native spawn
exception applies only to the requested Wallmaster actor while a validated private
MM Wallmaster layout is active in a randomizer game. Its full-function host test
compiles both combo and standalone paths, compares 288 cases per path with the
upstream hook, and retains soul, object-slot, boss, allocation and initialization
guards. This repairs the existing four-source private profile; it adds no pool,
setting, layout format or public entrance capability.

The OoT edge-binding exporter turns the reviewed `oot-edge-audit.json` into
`combo_oot_edge_bindings.inc` (native) and `OotEdgeBindingNames.h` (names only) for
the generation-only opposite-age Temple probe. Tranche 1 binds the three OoT one-way
rows (`OOT_LAKE_HYLIA_FROM_VALLEY`, `OOT_FIELD_OWL`, `OOT_VILLAGE_OWL`) as candidate
edges and the two spawn rows for the probe's root policy only. For every row it
re-checks the registry type, one native exit from the parent to the target, the
Ship `entranceShuffleTable` row and entrance index (or the audited adult-spawn
alias), the absent reverse, and each file:line of evidence. The probe is not wired
into generation and no entrance capability is enabled.

The M1 contract exporter writes `m1-contract.json`, the shared fixture for Wallmaster
Shuffle and One-Ways Shuffle (Own Game). It re-implements the v32.3 pool rules of
`packages/logic/src/solver/entrances.ts` in Python, independently of `Shuffle.h`, and
runs them over the pinned registry and every world area file (read with a restricted
YAML reader that fails closed). It covers the 66 normalized combinations of
`erWallmasters` and `erOneWays` (none or Own Game) and the five one-way flags, with
every other er* key at its default: active pools, per-source candidates,
`can_reset_time`-gated destinations and water-void dead ends. It also records the
active OoT Wallmaster sources for all 64 vanilla/MQ choices of the six Wallmaster
dungeons (with the 12-source, 11-destination capacity cases), the Wallmaster and
one-way source edges with file:line, the `er_enabled` and `isEntranceShuffle` tables,
the MM logic lines that reach `er_enabled`, the ER-wide runtime sites (`CFG_ER_ANY`,
`PG_ER` hot water at `0x8010eba0`, `CFG_ER_WALLMASTERS`, `PG_ER_WALLMASTERS`) and the
spoiler "Entrances" format. For every combination it checks that `processRegions`
and `propagateDungeons` give the same hint regions and dungeon entrances as without
entrance shuffle. A sha256 of each cited upstream body is pinned in the exporter, so
a re-pin fails until the re-implementation is reviewed again.

`entrance_m1_pinned_contract_fixture` checks the fixture against independent
constants (13 + 4 Wallmaster rows, 23 + 4 edges and 24 soul lines, 11 / 7 and 14 / 14
candidates, OoT 3<->3 and MM 7<->7 permutations, per-flag counts) and, with the pinned
checkout, exact reproduction, read-only stale checks and wrong-pin refusal.
`entrance_m1_shuffle_pools_match_pinned_contract` runs the real `MakePools`,
`Shuffler` pool construction and `Assignable` candidate filter for every combination
in the all-vanilla world, and the Wallmaster pool for every vanilla/MQ choice, and
requires the same pools and candidates. Nothing here enables a setting, a pool or a
layout format.

`er-enabled-sites.json` is a reviewed receipt, not exporter output. It lists every MM
logic line of the contract's `erLogicSites` (the macro closure of `er_enabled`) with
the fork statement that now carries `has_hot_water_er` or the reason it has none: the
Snowhead lines reach it only through `trick(MM_SHT_HOT_WATER)`, which the port does
not have, and the two Goron Elder lines share the fork's one Elder check. The two
Twin Islands lines carry it through `CAN_BRING_HOT_WATER_NORTH` (`carriers`), so the
Goron Elder's condition text, which the MM Check Tracker shows, stays as it was. It also
names the `PG_ER` hot-water patch target, `Interface_StartBottleTimer` at
`0x8010eba0`, from the MM decomp's US symbol map and OoTMM's own link addresses.
`mm_er_enabled_sites_flags_and_exports` and
`mm_er_hot_water_never_cools_under_entrance_shuffle` check it against the contract,
the production sources and, when it is present, the pinned checkout.

`compare_m1_pinned_node.py` cross-checks that fixture against OoTMM's own TypeScript,
run by the pinned portable Node v24.21.0 (no npm install; packages come from the
checkout's `node_modules`). `run_pinned_entrance_pools.mts` serves every OoTMM source
and data file from its Git blob at the pin, rebuilds `@ootmm/core`'s data with the
pinned build script in memory, and builds each combination's world as OoTMM does
(`options()`, `worldState`, price and song events). It changes OoTMM code in memory in
three places, and lists all three in the facts (`inMemoryChanges`):

- `packages/core/build/helpers.ts`: its `node:fs` import resolves to a small shim whose
  `readFileSync` / `globSync` serve the pinned blobs and whose `writeFileSync` /
  `mkdirSync` keep the build output in memory;
- `packages/core/build/helpers.ts`: `const __dirname = "<checkout>/packages/core/build"; `
  is prefixed to line 1 (tsx ran it as CommonJS, where `__dirname` exists);
- `packages/logic/src/solver/entrances.ts`: `export { WorldShuffler, LogicPassEntrances };`
  is appended so those classes can be driven.

A re-pin where `helpers.ts` stops using `__dirname` or those four `fs` functions needs
the runner's hooks updated. The runner records the
pools `placePools` builds, the `isAssignableConstraints` candidates, the
`placeSingleExpr` reset gate, dead ends, `er_enabled` / `isEntranceShuffle`, the
`changedWorld` + `processRegions` region results, one seeded `WorldShuffler.run()`
per combination, and the OoT Wallmaster sources of all 64 vanilla/MQ choices (with a
real attempt for every capacity case). The comparer reports each disagreement with
both values and the pinned file:line, and never edits the fixture. The facts also
record the sha256 of the contract bytes the run read (its sample layouts, rows and
combination list come from them), so comparing saved facts (`--facts` without
`--node`) with a changed fixture is reported as a divergence; rerun with `--node`:

```sh
python tools/ootmm/compare_m1_pinned_node.py --reference /path/to/ootmm-stable-32.3 \
    --node /path/to/node-v24.21.0/node.exe --out report.json
```

`entrance_m1_contract_matches_pinned_ootmm_run` runs it (about 100 s on 8 worker
threads) and checks that the comparer names altered fixture values and altered pinned
facts and rejects saved facts made from another fixture; it reports SKIPPED without the
pinned Node or the checkout.
