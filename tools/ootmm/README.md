# Pinned entrance metadata

The exporters require a local OoTMM v32.3 checkout whose HEAD is exactly
`413573d22d1d53e8a81931a70927f625b73488b9`. They read immutable Git blobs with
`git show`, so checkout line endings and uncommitted file edits cannot alter the
source digest. Python 3 and Git are the only dependencies; there is no network or
reference-checkout mutation. Unrecognized registry syntax fails closed.

Run from this repository, substituting the path to that checkout:

```sh
python tools/ootmm/export_registry.py --reference /path/to/ootmm-stable-32.3
python tools/ootmm/export_grotto_context.py --reference /path/to/ootmm-stable-32.3
python tools/ootmm/export_registry.py --reference /path/to/ootmm-stable-32.3 --check
python tools/ootmm/export_grotto_context.py --reference /path/to/ootmm-stable-32.3 --check
```

`--output-root` defaults to this repository and can point at a scratch directory.
`--check` compares exact LF UTF-8 bytes and exits unsuccessfully on missing or stale
output without writing files. Formatting of generated tables is deterministic and
does not depend on a locally installed formatter. Narrow `.gitattributes` rules
preserve canonical LF output even in Windows checkouts using `core.autocrlf=true`.

The registry exporter writes `combo/rando/entrances/Registry.h`, its upstream
license, and `registry-source.json`. The context exporter validates the 13 generic
grotto content codes, 24 source-qualified MM exits, and mountain winter exception
against the pinned runtime before writing `GrottoMetadata.h` and its manifest.
Other native binding/arrival adapters are not outputs of these exporters.

Compared with the previous 611-row master registry, v32.3 has 608 rows. The removed
records are unused type-none `OOT_BOSS_GANONDORF`, `MM_BOSS_MAJORA`, and `MM_BOSS_IGOS`.
Seven OoT records have different area metadata. All remaining MM records retain
their semantic fields; the extracted MM grotto runtime tables are identical.

Existing MM-only saved profiles and their oracle assumptions deliberately keep
the old master commit and historical CRLF-byte hash in `LegacyEnvelope.h`. Their
writers, readers, profile names, and schema versions retain that contract. The
legacy fixture in `ComboAndroid/tests/fixtures/entrances-legacy-v1.json` was captured
before the repin and must not be regenerated by an exporter. The current registry
identity is available for a future unified format; this change does not enable
that format or any public entrance settings.

Host coverage is registered in `ComboAndroid/tests/CMakeLists.txt`: legacy profile
and route compatibility, compiled registry/context metadata, and exact-reference
export reproducibility with wrong-pin and stale-output rejection. The reference
test uses `COMBO_OOTMM_REFERENCE` or discovers `references/ootmm-stable-32.3` in an
ancestor directory. It reports an explicit skip when that optional checkout is
absent; compiled metadata and legacy-route checks still run.
