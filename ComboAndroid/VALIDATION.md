## Test environment and privacy

User-supplied OoT USA NTSC 1.0 and MM USA 1.0 ROMs were imported using Android's document picker. MM's byte-swapped input was normalized by the production importer. Normalized hashes matched the local source copies. Both engines extracted their game archives successfully and reused them on subsequent launches. ROMs, extracted archives, test saves, exported backups, screenshots and runtime logs remain local and are excluded from the APK and source ZIP. No ROM upload is part of the build or test workflow.

## Fixes driven by these tests

- Android extraction now uses the app's writable private cache as `TMPDIR`. The previous default `/data/local/tmp` caused real extraction to fail. Extraction exceptions are logged and the failure UI wraps its message.
- The floating Menu button no longer covers native tabs while the main menu is open. Android Back reaches the menu through SDL's key dispatch, while still dismissing the software keyboard normally.
- Opening the Android keyboard preserves existing native text. Seed-field preservation and search text entry were exercised.
- Disabled OoT diagnostic timers no longer read the clock during every logic query. Generation progress also reports pool preparation before placement starts.
- New linked MM saves receive the `ZELDA3` validity marker normally set by MM file select. Its absence had made the pause/owl writer discard the save. Loaded randomizer containers with the specific all-zero marker are repaired in memory; intentional invalidation in flash-save deletion paths is unchanged.
- OoT names are normalized from their saved NTSC/PAL encoding before copying into MM, including spaces and punctuation. A newly created NTSC name `A` was verified as MM code 10 followed by seven spaces, with a valid file marker.
- Backup export additionally excludes ZIP archives and the bundled controller database. A harmless ZIP-named sentinel verified that exclusion through the real export UI.
